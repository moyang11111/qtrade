# 模拟盘执行与次日验证

## 模块和数据

- `paper_trading/clock.py`：统一交易日历、连续交易时段和实时行情时间检查。日历不可用时暂停成交。
- `paper_trading/automation.py`：收盘信号、待执行记录、统一开仓风控、名单冻结和次日核对。主服务仅保留连接现有信号引擎的适配类。
- `paper_trading/engine.py`：资金、订单、成交、持仓和执行去重；每次成交与持仓来源元数据在同一 SQLite 事务内提交。
- 桌面账本位于用户状态目录的 `paper_trading/auto_paper_state.db`。旧数据库通过 SQLite backup 复制，旧 JSON 元数据导入同一数据库，旧文件保留供回退。旧 JSON 账本只迁移一次。

## 执行时序

已核验收盘快照（当日需15:30之后）→ 保存信号与快照版本 → 下一交易日有效交易时段 → 通过风控及行情检查 → 以当时非复权实时价模拟成交。

历史前复权收盘价用于研究和信号，不作为订单成交价格。行情需属于成交当日，距当前时间不超过120秒，未来时间误差不超过5秒，并且价格、成交量有效。休市、午休、过期快照、行情不可用时不成交；超过目标日的信号失效。

T+1 按实际成交日期记录持仓。执行去重键涵盖账户、模式、快照、股票、方向、信号日；后台轮询与手动操作串行化，同一键在重启或并发请求下最多成交一次。切换策略取消旧策略待执行信号；重置取消待执行记录。

策略和决策买入共同检查可交易状态、已有持仓、持仓总数、市场宽度、因子族集中度、资产高点回撤、可用资金及每轮新开仓上限。回撤从账户记录的资产高点计算。

费用包括佣金最低5元、佣金率0.03%、沪市过户费和卖出印花税0.05%。账户总资产收益已扣费用；持仓表的价差盈亏不等于最终扣费收益。成交仍是基于行情的模拟，没有逐笔订单簿和排队撮合。

## 名单验证

运行上涨研究后，后台即使处于暂停交易状态也可保存研究名单。相同模型和信号日的第一份名单不会被后来重算覆盖。只有在目标日开盘前生成、保存的名单才标为开盘前冻结；事后重算单独标为历史核对。

目标日完整收盘快照发布后，使用同一复权版本的信号日与目标日收盘价逐只比较，分别统计前10和前100名上涨、下跌、持平。缺失标签保持等待，不算作下跌。研究估计未通过质量门槛时仍可观察；该名单不会自动作为交易策略。

## 操作与迁移

### 三种交易模式

- 手动交易：输入6位代码、方向、股数，交易时段内以有效实时价成交。支持加仓和部分卖出，持仓显示可卖数量并可一键填入卖出表单。买入100股整数倍；卖出100股整数倍或一次卖出全部零股。T+1、价格限制、资金、持仓上限及账户回撤检查仍然有效；市场宽度和因子族筛选用于策略，不限制人工选择。手动模式不运行策略或自动止盈止损。
- 策略自动：收盘信号进入待执行队列，保持原有下一交易日执行流程。
- 人工确认：买卖建议（包括止盈止损）先进入待确认列表；确认后才进入待执行队列，也可以拒绝或取消。策略暂停时，已确认的订单等待恢复；“生成一轮建议”可在暂停状态扫描一次，已有批准订单也可在这一轮检查成交。

切换交易模式会暂停策略并取消未执行的建议和订单。再次切换不会使取消记录恢复。切换信号源同样取消旧策略建议。页面显示待确认、待执行、成交、拒绝、取消、失效记录；手动成交显示在最近交易中。

手动请求携带唯一订单标识，重复请求或重启后重试返回同一成交，不重复扣款。同一标识不能被用来修改股票、方向、数量。订单成交、执行标识、平均持仓价格、持仓来源仍在一个事务内保存。手动操作接口只接受同源POST和严格校验后的JSON字段。

模拟盘控制改为同源 POST；GET 状态只读。页面显示运行阶段、信号日、执行日、待执行记录、当前回撤及名单核对。

安装前备份旧软件资源与用户账本，迁移后核对现金、持仓、历史交易及暂停状态。可恢复旧资源和原始账本回退；不要用新生成的回测或历史核对结果改写旧交易记录。

## 验收

确定性隔离测试覆盖：休市和午休禁成交、旧行情拒绝、T+1、并发去重与重启恢复、事务回滚、收盘信号次日真实价格成交、过期信号、统一风险检查、名单冻结与未来标签隔离、事后名单分类。不会在验收时开启用户模拟盘或清空用户交易记录。
